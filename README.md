## 🎯 策略概览

本项目面向美国股票市场，采用规则化、系统化的交易框架，结合趋势跟随、短周期均值回归及市场状态识别，根据不同市场环境动态调整交易行为。

* **策略类型**：规则化市场状态自适应策略
* **主要市场**：美国股票市场（高流动性标的）
* **执行方式**：Python + Interactive Brokers (IB) TWS API 程序化直连
* **交易特征**：非高频交易，不依赖 Level 2、订单簿微观结构或超低延迟基础设施
* **研究方法**：历史回测、滚动样本外验证、参数敏感性分析及稳健性检验
* **知识产权**：策略代码、核心交易规则及关键参数不公开

### 策略核心框架

* **趋势跟随**：识别价格趋势及持续性特征，在符合策略条件的特定市场环境下参与趋势行情
* **短周期均值回归**：针对短周期价格偏离及均值回归特征进行交易，捕捉阶段性价格修复机会
* **市场状态识别**：根据市场波动、趋势强度及价格行为识别不同市场状态，并动态调整交易行为
* **规则化程序执行**：将交易条件、风险参数及执行规则程序化，减少主观判断对交易过程的影响

> *注：以上仅描述策略的宏观研究框架，不涉及具体信号公式、因子构成、参数范围或交易规则。*

## 🧪 研究与稳健性验证

策略研究采用分阶段验证框架，将策略逻辑研发、历史验证及实际市场执行观察进行区分。

### 分阶段研究与验证周期

* **策略开发期（2010–2020）**：完成策略逻辑、核心因子、交易规则及主要参数体系的研究与开发。该阶段属于研发探索期，不作为独立历史验证结果展示
* **历史验证期（2021–2025）**：在独立历史时间区间内进行系统化回测验证，重点观察收益、回撤、风险调整收益及不同市场环境下的表现
* **执行观察期（2025–2026）**：在真实市场环境下进行阶段性模拟与实盘执行观察，用于评估实际成交滑点、交易成本及系统运行稳定性

### 回测架构与稳健性控制

* 采用逐 Bar 前向状态机架构，按单一时间轴推进，避免未来数据泄露（Look-ahead Bias）。
* 回测基于市价单撮合，并将基于真实实盘成交数据校准的佣金模型与滑点模型纳入全成本计算。
* 参数经过系统化敏感性测试及滚动样本外验证（Walk-Forward），降低策略对单一局部最优解的依赖。
* 严格区分策略开发与历史验证阶段，并观察策略在趋势、震荡及高波动市场环境下的表现差异。
* 综合考察年化收益、最大回撤、最长回撤持续期、夏普比率及胜率等指标，并观察不同市场阶段下的表现稳定性。
* 采用组合对称交叉验证（CSCV）框架评估回测过拟合风险，并通过多个独立随机种子重复检验参数选择的稳健性。
* 多组独立检验结果显示，PBO（Probability of Backtest Overfitting）整体低于本研究采用的评价参考线。

> *注：具体 PBO 数值、参数敏感性结果及更详细的稳健性分析属于内部研究资料，不在公开页面展示。*

### 成本模型

历史回测成本模型基于真实实盘成交数据进行校准，包括实际佣金及滑点特征，并将相应成本模型纳入历史回测。与单纯采用理论佣金或固定滑点假设相比，该方法旨在使历史回测中的交易成本更接近实际执行环境。

* 年化收益受影响幅度低于 **0.3%**

## 🛡 风险控制框架

策略风控体系采用参数化、程序化的分级控制机制，覆盖账户资金、单笔交易、日内累计亏损、全局最大回撤及系统运行异常等多个层级。各层级独立触发并自动执行相应处理逻辑，风险控制规则优先于交易信号。

| 风险层级 | 主要控制内容 | 自动化处理 |
| --- | --- | --- |
| **单笔交易** | 单笔持仓及止损风险 | 触发条件后执行退出或限制后续交易 |
| **日内风险** | 日内累计亏损 | 达到阈值后停止新增交易 |
| **组合风险** | 全局最大回撤 | 触发后停止策略新增风险暴露并执行保护机制 |
| **集中度风险** | 单一标的及组合风险暴露 | 限制新增风险集中 |
| **系统风险** | API、行情、订单及程序运行异常 | 异常检测、停止交易及保护性处理 |

> 风控优先级：**全局回撤 > 日内累计风险 > 单笔交易风险**。所有风控逻辑在策略程序中强制执行，未通过风险校验的信号不会进入订单执行环节。

## ⚙️ 系统执行架构

策略采用 Python 与 Interactive Brokers（IB）官方 API 的程序化直连模式，构建覆盖行情接入、信号生成、风控校验、订单执行与日志监控的完整系统链路。

| 系统模块 | 技术说明 |
| --- | --- |
| **策略核心** | Python 程序化策略引擎 |
| **交易接口** | Interactive Brokers TWS API |
| **行情与执行** | 实时行情接入及程序化订单执行 |
| **风险控制** | 信号进入执行环节前进行程序化风险校验 |
| **运行环境** | 本地工作站或云端服务器 |
| **日志系统** | 交易、信号、订单、异常及系统状态结构化记录 |
| **监控机制** | 持续监控系统连接、行情、订单及运行状态 |

策略系统不依赖超低延迟基础设施，不以 Level 2 或订单簿微观结构为核心输入，定位为规则化、系统化的程序交易系统。

## ⚠️ 风险因素

量化交易及程序化交易存在包括但不限于以下风险：

* **市场风险**：股票价格可能发生快速及非预期波动。
* **模型风险**：历史数据中的统计规律可能在未来市场环境中失效。
* **执行风险**：实际成交价格可能与理论价格存在差异。
* **流动性风险**：特定市场环境下可能出现流动性下降及成交困难。
* **技术风险**：行情、网络、API、交易系统或服务器故障可能影响正常执行。
* **参数稳定性风险**：策略参数在不同市场阶段可能表现出不同的敏感性。
* **数据风险**：历史数据质量及数据处理方式可能影响回测结果。
* **回测局限性**：历史回测结果不代表未来实际交易表现。
* **实盘观察局限性**：阶段性实际执行样本不连续、不完整，不能视为长期实盘业绩记录。

## 🧠 研究背景与核心理念

本项目长期围绕系统化美股交易展开研究，重点关注：

* 市场状态识别
* 趋势与短周期价格行为
* 规则化交易系统
* 参数稳定性
* 历史回测可靠性
* 样本外验证
* 回测过拟合风险
* 实际交易成本
* 滑点与执行质量
* 程序化风险控制

研究过程中强调：

> **策略逻辑必须能够被明确表达、程序化执行，并通过历史数据与实际执行环境进行持续验证。**

项目不依赖机器学习黑盒模型，核心研究重点是规则化交易逻辑及其统计稳健性。

> **核心理念：用可重复系统替代主观判断，用规则约束交易行为。**

研究目标并非寻找某个历史区间内的单一最优参数，而是观察策略在不同市场环境、不同历史阶段及实际执行条件下是否能够保持相对稳定的风险收益特征。
